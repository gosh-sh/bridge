# Groth16 Wrapper for Ethereum Mainnet Deployment

## Problem Statement

The Halo2 verifier contract generated by `snark-verifier-sdk` is **28.8KB**, which exceeds Ethereum's **24KB contract size limit** (EIP-170). This prevents deployment on Ethereum mainnet.

## Solution: Groth16 Wrapper

We implement a **Groth16 wrapper** around the Halo2 proof, following the industry-standard approach used by production ZK systems (Succinct SP1, Linea zkEVM, Worldcoin).

### Architecture

```
┌─────────────────────────────────────────────────────────────┐
│                    Halo2 Circuit                             │
│              (Deposit Event Verification)                    │
│                    Degree 15, BN254                          │
│                    7 public instances                        │
└──────────────────────┬──────────────────────────────────────┘
                       │ generates
                       ▼
              ┌────────────────┐
              │  Halo2 Proof   │
              │  (PLONK/KZG)   │
              │  ~1.5KB        │
              └────────┬───────┘
                       │ wraps in
                       ▼
         ┌─────────────────────────┐
         │  Groth16 Circuit        │
         │  (gnark implementation) │
         │  Verifies Halo2 proof   │
         └────────┬────────────────┘
                  │ generates
                  ▼
         ┌────────────────┐
         │ Groth16 Proof  │
         │ ~200-300 bytes │
         └────────┬───────┘
                  │ verifies on-chain
                  ▼
    ┌──────────────────────────────┐
    │ Groth16 Solidity Verifier    │
    │ ~1-2KB (fits in 24KB limit!) │
    └──────────────────────────────┘
```

### Why This Works

1. **Groth16 verifiers are tiny**: ~1-2KB (vs 28.8KB for Halo2)
2. **Groth16 proofs are constant-size**: ~200-300 bytes
3. **Groth16 verification is cheap**: ~280k gas on mainnet
4. **Production-proven**: Used by major ZK systems

## Implementation Components

### 1. Halo2 Proof Parser (Rust)
- **Location**: `src/groth16_wrapper/proof_parser.rs`
- **Purpose**: Parse `Snark` struct from `snark-verifier-sdk`
- **Extracts**:
  - KZG polynomial commitments (G1 points)
  - Polynomial evaluations (field elements)
  - Public inputs (7 instances)

### 2. Groth16 Verifier Circuit (Go/gnark)
- **Location**: `gnark-wrapper/circuit.go`
- **Purpose**: Implement PLONK verification logic in Groth16 circuit
- **Verifies**:
  - KZG commitment openings
  - Polynomial evaluation checks
  - Pairing equations
  - Public input constraints

### 3. Rust-Go FFI Bridge
- **Location**: `src/groth16_wrapper/ffi.rs` + `gnark-wrapper/ffi.go`
- **Purpose**: Pass proof data from Rust to Go
- **Uses**: CGO for C-compatible FFI

### 4. Groth16 Prover (Go/gnark)
- **Location**: `gnark-wrapper/prover.go`
- **Purpose**: Generate Groth16 proof and Solidity verifier
- **Outputs**:
  - Groth16 proof file
  - Solidity verifier contract (~1-2KB)

## Usage

### Generate Groth16-Wrapped Proof

```bash
# 1. Generate Halo2 proof (existing workflow)
cargo run --release --example test_with_real_data

# 2. Wrap Halo2 proof in Groth16 (new)
cargo run --release --example generate_groth16_proof -- \
    --halo2-proof deposit_proof_output.json \
    --output groth16_proof.json

# 3. Generate Solidity verifier (new)
cargo run --release --example generate_groth16_verifier -- \
    --output Groth16Verifier.sol
```

### Deploy Verifier

```bash
# Deploy the tiny Groth16 verifier (1-2KB)
forge create --rpc-url $RPC_URL \
    --private-key $PRIVATE_KEY \
    Groth16Verifier.sol:Groth16Verifier

# Verify proof on-chain
cast send $VERIFIER_ADDRESS \
    "verifyProof(bytes,uint256[])" \
    $(cat groth16_proof.json | jq -r .proof) \
    $(cat groth16_proof.json | jq -r .publicInputs)
```

## Technical Details

### Halo2 Proof Structure (PLONK/KZG on BN254)

The Halo2 proof contains:
- **Commitments**: G1 points on BN254 curve
  - Advice commitments
  - Permutation commitments
  - Lookup commitments (if used)
- **Evaluations**: Field elements (Fr of BN254)
  - Polynomial evaluations at challenge point
  - Permutation evaluations
- **Opening Proof**: KZG proof (G1 point)
- **Public Inputs**: 7 field elements
  - depositId, sender, amount, contract_address
  - block_hash_high, block_hash_low, promise_commit

### Groth16 Circuit Constraints

The gnark circuit must verify:

1. **KZG Commitment Opening**:
   ```
   e(C - [v]₁, [1]₂) = e(π, [x]₂ - [z]₂)
   ```
   Where:
   - C = polynomial commitment (G1)
   - v = evaluation at point z
   - π = opening proof (G1)
   - x, z = field elements

2. **PLONK Gate Constraints**:
   ```
   q_L·a + q_R·b + q_O·c + q_M·a·b + q_C = 0
   ```

3. **Permutation Argument**:
   Verify copy constraints using grand product argument

4. **Public Input Binding**:
   Ensure public inputs match circuit outputs

### Security Considerations

1. **Trusted Setup**: Groth16 requires circuit-specific trusted setup
   - Use Powers of Tau ceremony (e.g., Hermez/Polygon)
   - Or use universal setup (PLONK) if available in gnark

2. **Soundness**: The Groth16 wrapper must correctly verify ALL Halo2 constraints
   - Extensive testing required
   - Consider formal verification

3. **Completeness**: Valid Halo2 proofs must always produce valid Groth16 proofs
   - Test with many proof samples

## FAQ

**Q: Why not just use Halo2 aggregation?**  
A: Even aggregated Halo2 verifiers are 15-25KB, still too large for mainnet.

**Q: Why Groth16 instead of PLONK?**  
A: Groth16 verifiers are smaller (~1-2KB vs ~2-5KB for PLONK).

**Q: How long does Groth16 wrapping take?**  
A: Estimated 30-60 seconds per proof (acceptable for bridge use case).

**Q: Can we use SP1's gnark-ffi directly?**  
A: No, SP1's gnark-ffi is tightly coupled to SP1's internal proof format.

**Q: Is this production-ready?**  
A: After thorough testing and auditing, yes. This is the standard approach used by major ZK systems.
