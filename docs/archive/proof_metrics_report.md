## 6. On-Chain Gas Costs (Ethereum)

### Pure Groth16 Verification (`verifyLayerHashUpdate`)

| Fixture   | Gas         | Notes |
| --------- | ----------- | ----- |
| L2_H16    | **286,672** |       |
| L2_H32    | **286,870** |       |
| L5_H12288 | **287,037** |       |
| L6_H45056 | **286,891** |       |

**Verification cost is ~287K gas** — effectively constant across all fixtures. The dominant cost is the `ecPairing` precompile (EIP-197) for the BN254 pairing check, which is independent of the number of public inputs at this scale.

### Full Bridge Update (`updateLayerHashes`)

| Fixture              | Gas         | Breakdown                         |
| -------------------- | ----------- | --------------------------------- |
| L2_H16 (2 layers)    | **414,168** | ~287K verify + ~127K state writes |
| L5_H12288 (5 layers) | **484,608** | ~287K verify + ~198K state writes |
| L6_H45056 (6 layers) | **504,693** | ~287K verify + ~218K state writes |
| L5 (gas report test) | **456,874** | Measured via gasleft() delta      |

Bridge update cost scales with number of layers due to `SSTORE` operations for `currentLayerHashes[10]`. The difference between 2 layers and 6 layers is ~90K gas.

## 7. Size Comparison: Halo2 vs Groth16

|                   | Halo2 (SHPLONK) | Groth16 (BN254)      | Compression              |
| ----------------- | --------------- | -------------------- | ------------------------ |
| Proof size        | 24 KB           | 256 B                | **96x** smaller          |
| Verification cost | ~ms (native)    | ~287K gas (on-chain) | N/A (different contexts) |
| Proving Key       | 5.3 GB          | 2.4 KB               | N/A (different circuits) |
| Verification Key  | 11 KB           | 748 B                | ~15x smaller             |

The Groth16 wrapping achieves a **96x proof compression** (24 KB → 256 bytes), making on-chain verification feasible at ~287K gas per proof.

## 8. Production Considerations

- **Key reuse**: One keygen produces PK/VK that work for all fixtures with the same circuit parameters (same K, same LAYER_TREE_DEPTH). No per-fixture keygen needed.
- **PK storage**: The 5.3 GB proving key must be loaded by the prover at startup. This is the main memory requirement for the relayer service.
- **Production LAYER_TREE_DEPTH=8**: Will require re-keygen with production parameters. Circuit size may increase, potentially requiring larger K or more columns.
- **Parallelism**: Proof generation for different blocks can run in parallel if multiple PK copies are loaded.
